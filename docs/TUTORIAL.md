# FeatureUnit 上手教程

> 手把手走完"从一句话需求到功能上线"。两条路线：
> **路线 A（推荐）：流水线**——人只说一句话，系统逐步生成，你逐步确认；
> **路线 B（手动）：分步操作**——理解每个环节后，用管理台/CLI 逐步执行。
> 前置：Node ≥ 20；读完 `USAGE.md`。

## 第 1 步：路线 A——一句话需求走流水线

**场景**：需求"支持用户收藏商品"。

### 1.1 开始

管理台 **🏠 开始**页 → 输入 `支持用户收藏商品` → 「开始自动开发」。

系统自动规划（`analyzeRequirement` 关键词解析）：

```
📋 新业务域 → 创建服务组 favorite-service
📋 需要数据切面 → 生成端口 favorite-item
📋 核心动作 → 单元 toggle-favorite
```

### 1.2 逐步确认（每步看产物 + 机器判据，再点确认）

| 步 | 你看到的 | 你要做的 |
|---|---|---|
| ① 规划 | 方案 + 理由 | 确认 |
| ② 端口 | Agent-D 草稿 + 7 项初审（⚠️ 缺 JSDoc 等纪律项） | 确认 → 冻结 |
| ③ 契约 | Agent-A 草稿 + 初审（结构/端口引用/tsc） | 确认 → 冻结 |
| ④ 判据 | Agent-B 骨架（N 条不变量 → N 个 it） | **到「单元」页补全断言** → 回来确认冻结 |
| ⑤ 实现 | Agent-C 迭代轮次（判据红→重试→全绿或停手） | 确认（含接受"停手求援"） |
| ⑥ 打包 | Agent-E 接线 + **tsc 预演**（编译不过禁止确认） | 确认落盘 |
| ⑦ 完成 | 🎉 | 总闸 + 冒烟 |

### 1.3 关键体验

- **占位判据会被拦截**：第 ④ 步直接确认会报"判据仍是占位——请先补全断言"。这是纪律：考卷没写完不许开考；
- **坏接线会被拦截**：第 ⑥ 步如果 tsc 预演失败，确认按钮不生效（机器判据闸门）；
- **mock vs 真实**：没有 API Key 时 mock 模式走完全相同的流程，产物含刻意缺陷（正好练评审）。

## 第 2 步：路线 B——手动分步

想理解每个环节，或流水线不方便时，手动分步：

### 2.1 建组 / 建单元

```bash
npm run feat -- new-group order-service          # 新组（或面板 ＋）
npm run feat -- new create-order --group order-service
```

生成 4 文件模板：`contract.ts`（契约）/ `spec.md`（规格）/ `impl.ts`（实现桩，必红）/ `impl.test.ts`（判据占位）。
⚠️ 占位判据 `expect(true)` 是"假绿"——判据没写之前**不许发给 AI 实现**。

### 2.2 契约（Agent-A）

```bash
npm run feat -- ai-contract create-order "创建订单" --group order-service --mock
# 真实模式去掉 --mock（需要 AI_API_KEY）
```

流程：生成草稿 → 机器初审（结构/端口引用/tsc）→ **你逐条过 10 项评审清单（y/n）** → 冻结（git 提交）。
管理台同款：📦 单元 → ① 契约阶段。

### 2.3 判据（Agent-B）

管理台「AI 生成判据」→ 生成骨架（每条不变量一个 it，显式 TODO 必红）→
**人工补全断言**（或管理台编辑文件）→ 「确认判据（冻结）」。

> 判据质量决定一切：契约是考卷，判据是阅卷机。补全时覆盖失败路径（错误码断言）、
> 安全不变量（防枚举/全端下线/PII 不进日志）。

### 2.4 实现（Agent-C）

```bash
npm run feat -- ticket create-order    # 打印任务单
# 整段发给 AI，AI 只写 impl.ts → 判据全绿才提交
# 或管理台「AI 实现（自动迭代）」：内置迭代器，红→重试≤5 轮
```

**判据红不许改判据**——纪律红线。

### 2.5 打包（Agent-E）

管理台「🤖 AI 打包」→ 生成接线（组合根/HTTP/manifest）→ **tsc 预演**（自动还原）→ 人确认落盘。
或「🔌 接线检查」看缺口 + diff 预览。

### 2.6 总闸与上线

```bash
npm run check    # tsc + 全部测试
npm run dev      # 冒烟：注册/登录/查我（或管理台 🧪 试玩）
```

## 第 3 步：机器判据详解（框架的"考试系统"）

| 环节 | 机器判据 | 不过会怎样 |
|---|---|---|
| 端口（Agent-D） | 7 项纪律初审：纯接口/无实现/零 import/无基础设施字样/一句话/Promise/方法带 JSDoc | 初审 ⚠️，人可打回 |
| 契约（Agent-A） | 结构（schema/编号不变量≥3/spec 章节）+ 端口引用存在性 + tsc | 初审 ⚠️，10 项评审拦截 |
| 判据（Agent-B） | 占位检测（TODO / expect(true) 一律拒绝冻结） | 冻结被拒：先补全 |
| 实现（Agent-C） | 判据全绿才提交；迭代 ≤5 轮超限停手 | 停手求援（失败安全） |
| 打包（Agent-E） | **tsc 预演**：写入→编译→自动还原 | 编译不过，确认按钮不生效 |
| 全局 | 冻结守卫：已冻结契约/判据/端口禁止被 AI 覆盖 | 报错：走契约演进 |

**初审本身也被"真实 AI 生成测试"校准过**：曾抓出 JSDoc 多行注释误报、不变量计数方式两个 bug——mock 的固定缺陷喂不出这种问题。

## 第 4 步：数据层（内存 → SQLite）

```bash
npm run migrate                       # 建表（幂等）
USER_STORE=sqlite npm run dev         # 真库运行
# 或管理台「配置」→ 存储模式下拉选 sqlite（保存后试玩面板自动生效）
```

| 存储 | 用途 | 数据在哪 |
|---|---|---|
| `memory` | 默认/判据/演示 | 进程内存 |
| `file` | JSON 文件持久化演示 | `data/users.json` |
| `sqlite` | 真库（唯一约束兜底并发） | `data/auth-service.db` |

SQLite 适配器行为与内存版一致（集成测试逐方法对照），`email UNIQUE` 约束把并发抢注转成 `EMAIL_TAKEN`。

## 第 5 步：AI 配置

管理台 **⚙️ 配置** tab：

| 项 | 填什么 |
|---|---|
| `AI_API_KEY` | 你的密钥（打码保存，不进 git） |
| `AI_MODEL` | **下拉自动获取**（或手填 `deepseek-v4-flash` / `deepseek-v4-pro`） |
| `AI_REASONING` | `low`（快省）/ `medium`（默认）/ `high`（深度推理） |
| `AI_BASE_URL` | 默认 `https://api.deepseek.com`，可换任意 OpenAI 兼容端点 |

**推理等级在流水线中自动分配**：契约/判据 = high，端口/实现/打包 = medium。
`deepseek-chat` 已停用（2026-07-24），迁移只改 AI_MODEL 一行。

## 实战教训（本仓库真实踩过）

1. **判据红着不许发 ticket**——占位 `expect(true)` 是假绿；判据骨架（TODO）必须先补全再冻结；
2. **AI 草稿必有洞**——评审永远假设它漏了安全边界，逐条过清单；
3. **判据会抓实现的语义错误**——"幂等成功 = 不做任何修改（含不清会话）"这类细节，正是判据锁行为的意义；
4. **冻结区守卫**：契约/判据/端口冻结后禁止被 AI 覆盖（lib + 前端双重拦截）；
5. **检查器也要被真实数据测试**——真实 AI 生成测试一次抓出初审 2 个假阴性 bug；
6. **`git add -A` 是双刃剑**——所有落盘动作强制 git 提交 = 留痕，也是事故保险（未提交代码曾两次从悬空提交完整找回）；但 **`git reset --hard` 会连带清掉未提交代码**——先提交代码、再演示、再只回滚演示提交（本项目踩过三次）；
7. **TS 注释里的 `*/` 陷阱**——块注释中出现 `**/impl.ts` 会提前截断注释（踩过两次）；
8. **mock 草稿要可编译**——违规 import 注释化展示，否则会破坏 tsc 总闸；
9. **配置来源要能看出**——面板标注"本地配置/环境变量/默认值"，改错了一眼定位；
10. **界面操作全部 git 留痕**——你在管理台的每个确认/编辑都可追溯（曾靠它定位"神秘提交"的来源：就是人点的）。
