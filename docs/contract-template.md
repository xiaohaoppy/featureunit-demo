# 契约模板：FeatureUnit 六要素（v1）

> 用途：给"契约设计师"（人或 AI）填写。一份契约 = 一个功能单元的全部规格。
> 对应代码：`contract.ts`（可执行部分：zod schema + 接口）+ `spec.md`（语义部分：本文档的落地形态）。
> 参考实例：`src/groups/auth-service/features/login/`（契约 + 规格 + 判据齐全）。

---

## 1. 一句话目标

用一句话说清"这个单元做什么"。写不出一句话 = 拆得不够细，回去重拆。

```
用户提交邮箱 → 系统发一封带重置链接的邮件。本单元不负责邮件内容。
```

## 2. 输入

列出每个输入字段 + 类型 + 边界规则。边界校验写进 zod schema（这是可执行的部分）。

```
{ email: string, 合法邮箱格式 }
语义约束：即使邮箱不存在，也必须返回成功（防枚举攻击）。
```

## 3. 输出

成功返回什么（结构化）；失败怎么表达（抛 AppError，见第 4 节）。

```
成功 → void。失败 → 抛 AppError，错误码见第 4 节。
```

## 4. 错误码

每个失败路径一个错误码 + HTTP 状态码。**问自己：每个输入/每个端口调用可能失败吗？失败是什么码？**

```
- INVALID_INPUT (400)：email 格式非法（zod 兜底，单元可假定已校验）
- RATE_LIMITED (429)：同一邮箱 10 分钟内超过 3 次（由注入的限流端口判定）
```

## 5. 端口（外部世界的唯一切口）

列出本单元依赖的所有端口 + 每个端口"为什么需要"。**规则：端口里禁止出现 ORM / HTTP / 框架类型；语义必须能被内存适配器完整模拟。**

```
- users: UserStore          # 查邮箱是否存在
- mail: EmailSender         # 发邮件
- tokens: ResetTokenStore   # 存 token（含过期时间）
- rate: RateLimiter         # 限流判定
- now: () => Date           # 时钟注入（测试可固定时间）
```

## 6. 不变量 / 边界情况（AI 必须满足的硬约束）

至少 3 条，**每条都必须可被测试断言**（写不出来测试的"不变量"是伪要求）。用【不】开头显式声明非目标。

```
- 邮箱不存在 → 不发邮件、不写 token、返回成功（防枚举）
- 重复请求 → 旧 token 作废，只保留最新一个
- token 有效期 30 分钟，过期后查询返回 null
- 【不】负责：邮件模板、链接跳转、新密码的复杂度校验
```

---

## 填写纪律（给契约设计师）

1. **只写规格，不写实现**——契约里出现"用 X 框架/库"字样 = 越界，删掉；
2. 每个端口都要问："端口背后的实现细节，单元需要知道吗？"——不需要就抽象掉；
3. 每个输入都要问："这值非法会怎样？"——必须给出错误码；
4. 不变量必须 ≥ 3 条且条条可测；
5. 语义用中文，签名用 TypeScript。
