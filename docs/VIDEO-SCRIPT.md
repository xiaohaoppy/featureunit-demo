> **本脚本从完整对话记录（08-14 ~ 08-16，60 轮）逐轮还原**，不只记录"做了什么"，
> 还记录**每个阶段当时在想什么、为什么这么决定、放弃了什么、踩了什么坑、留下了什么伏笔**。
> 拍摄建议：录屏 + 口述旁白，或逐幕做 slides + 配音。全片约 20 分钟，可拆两集（上：第 1-6 幕；下：第 7-11 幕）。
> 每幕的【旁白】是"当时的想法"，【金句】可做字幕/封面字。

# 上集 · 从零到能用（第 1-6 幕）

## 第 1 幕 · 缘起：判据客观是第一性原理（08-14 上午，轮 1-5）

| 项 | 内容 |
|---|---|
| 画面 | 白板/幻灯片：三层架构图（功能单元 / 端口-适配器 / 服务组）慢慢画出来 |
| 旁白 | 一切从一个痛点开始：**AI 写代码我们不敢放心**。不敢放心有两个原因——没有确定性的"完成判据"，以及每次任务的上下文太大。所以第一性原理是：**把开发单元缩到极致，把完成标准变成机器可判定**。功能单元四件套：契约（考卷）、实现（AI 唯一要写的）、测试（阅卷机，先写好）、规格说明。AI 不许改契约，不许改测试——**改了判据就是作弊**。然后用户问：怎么组合一个有用的服务？这引出了三层架构，关键取舍是**放弃微服务式的网络通信**——功能单元之间不走网络，避免了分布式复杂度。第一个架构修正也随之而来：登录系统拆成 7 个单元后，发现 login 和 register 要读写同一张用户表——**共享端口必须提升到组级**，于是有了"组合根"——唯一知道一切的文件，人维护。 |
| 金句 | 判据客观是第一性原理；AI 不许改契约，不许改测试 |
| 想法流 | 判据客观 → 需要测试 → 测试要内存适配器 → 需要端口抽象 → 端口要共享 → 组级端口 → 组合根 |

## 第 2 幕 · 纪律设计：test oracle 独立性（08-14 上午，轮 3-5）

| 项 | 内容 |
|---|---|
| 画面 | 三张角色卡（A 写契约 / B 写测试 / C 写实现）与"生成者 ≠ 判据者 ≠ 实现者"大字 |
| 旁白 | 用户问"契约怎么写，能用 AI 生成么"——这是分水岭。我意识到：如果让 AI 自己出题自己考，判据就废了。所以确立 **test oracle 独立性**：Agent-A 起草契约 → 人评审冻结 → Agent-B 写测试 → Agent-C 写实现。契约是六要素，里面有一条关键设计——**【不】负责声明**：显式声明这个功能不管什么，防止 AI 越界。评审清单 10 条，实战证明 AI 草稿会被揪出 4 个安全洞（防枚举、token 生命周期、重复请求、限流）——这就是分工的意义：**AI 翻译需求，人钉风险**。语言选型也从这个视角出发：不选"性能最好的"，选"AI 写起来质量最高的"——TypeScript 胜出，因为类型约束强，**编译器是第一道免费判据**。 |
| 金句 | 生成者 ≠ 判据者 ≠ 实现者；AI 翻译需求，人钉风险 |

## 第 3 幕 · 第一次落地：判据兜底被实证（08-14 下午，轮 6-9）

| 项 | 内容 |
|---|---|
| 画面 | 终端跑测试 → 红灯截图 → 修复后绿灯；git log 展示 7 次提交 |
| 旁白 | 用户要求"每一步做个案例，我要看到"。于是落地了第一个 demo：用"修改邮箱"走完 8 步流程。最有价值的瞬间不是功能完成，而是**判据真的抓到了 bug**——实现漏了"幂等分支要清会话"，测试红了。那一刻框架的价值第一次被实证：**想漏了 = 红灯，而不是上线后炸**。随后用户说"加个简单的 AI 功能：AI 生成第一步，用户确认对不对"——这就是"AI 生成 + 机器初审 + 人确认 + 冻结守卫"的万能模板，它成了后面所有环节的骨架。注意一个安全侧设计：**冻结默认打回**——没有明确确认就等于不通过。 |
| 金句 | 想漏了 = 红灯，不是上线后炸；冻结权永远在人，默认打回 |

## 第 4 幕 · 界面化：把纪律搬进管理台（08-14 下午，轮 10-17）

| 项 | 内容 |
|---|---|
| 画面 | 管理台界面逐步搭建：开始页 → 配置 tab → 编辑器浮层 → 试玩面板 |
| 旁白 | 用户要"设计一个界面管理这个事情"。我做了三个关键决策。第一，**CLI 和界面共用同一个核心库**——杜绝两个入口行为不一致。第二，配置四写法分档，推荐"本地配置 → 环境变量 → 默认值"，密钥打码保存、标注来源。第三，也是最重要的：**界面上每个编辑都要填说明并 git 留痕**——这个设计后来救了我们四次。还有一条纪律底线：组合根接线保持人工——**界面不替代纪律，只替代操作**。 |
| 金句 | 界面不替代纪律，只替代操作；每个操作都 git 留痕 |

## 第 5 幕 · 简化循环：人的工作从"写"变成"审"（08-14 傍晚，轮 18-22）

| 项 | 内容 |
|---|---|
| 画面 | 摩擦点地图：两个红色标记（写判据、接线）逐个变绿 |
| 旁白 | 用户问"还有什么进步空间让使用者更简单"。我画了张摩擦点地图，锁定两个纯人工环节：写判据、接线。核心洞察是：**它们正好能用我们已经确立的"AI 生成 + 人确认"模式解决**。于是 AI 生成判据、内置实现器（自动迭代、红就重试、超 5 轮停手求援）、端到端向导、一键接线（git diff 展示、人确认才落盘）全部落地。人的角色整体从"写代码"降级为"审代码"——**简化的正确姿势，是把人的工作从写变成审**。这轮还踩了第一个大坑：git reset --hard 清掉了未提交的代码，靠"全部动作 git add -A 提交"从悬空提交里完整找回——留痕设计成了事故保险。 |
| 金句 | 简化的正确姿势：把人的工作从"写"变成"审"；git 留痕 = 事故保险 |

## 第 6 幕 · 数据库与 Agent 体系：红利兑现（08-15 上午，轮 23-30）

| 项 | 内容 |
|---|---|
| 画面 | SQLite 适配器接入动画：buildDeps 换一行 → 8 个单元零改动；四张 Agent 卡补成五张 |
| 旁白 | 用户说"对接数据库，你先给个意见"。这是框架红利的兑现时刻：对接数据库 = 写一个适配器 + buildDeps 换一行，业务单元零改动。选型上坚持**不引重型 ORM**——实体类型会泄漏进端口，违反纪律。用户拍板"方案 B：一库多 schema，先做 SQLite 版"。这轮还发生了一件暴露漏洞的事：用户亲手在界面上触发了"AI 生成判据可以覆盖已冻结判据"——**界面化引入新漏洞，纪律守卫必须同步机器化**，于是加了 lib + 前端双重拦截。随后补齐端口统一管理、Agent-D 端口作者——四 Agent 齐了。还发现了 mock 生成器的真实局限：固定模板不读描述，于是把 mock 定位成"练评审的坏学生"，让它坏在纪律上（缺 JSDoc、同步返回），而不是坏在语义上。 |

## 第 7 幕 · 真实检验：检查器也要被真实数据测试（08-15 下午，轮 31-35）

| 项 | 内容 |
|---|---|
| 画面 | mock 生成的"坏学生"端口 vs 真实 AI 生成对比；tsc 预演写入→编译→自动还原动画 |
| 旁白 | 用户较真了："内置模拟 AI 是什么？你做过 AI 生成测试么？我需要你做一次。"于是我用自己当"真实模型"，严格按 prompt 纪律生成——特意选 mock 关键词覆盖不到的领域。结果抓到检查器 2 个假阴性 bug：JSDoc 只认单行注释、不变量按字词计数而不是按条目数。**mock 的固定缺陷喂不出这种问题，只有真实产物的风格差异能暴露检查器的问题**——此后每次重大改动都要跑一次真实生成测试。同一阶段还完善了打包预演：接线草稿真写入文件 → 全项目 tsc → git 自动还原——**接线能不能编译，只有真编译才知道，而且预演必须零污染**。 |
| 金句 | mock 练流程，真实产物练检查器；预演必须零污染 |

## 第 8 幕 · 一句话开发：超级向导与工程瘦身（08-15 下午，轮 36-43）

| 项 | 内容 |
|---|---|
| 画面 | 9 个 tab 收成 6 个 tab 的前后对比；开始页一句话输入框；推理等级下拉 |
| 旁白 | 五 Agent 齐了，但操作太碎——"人确认"点太多。用户说"人只需要说什么功能，自动生成全部，一步步实现，由人确认"。于是有了**超级向导**：一句话需求 → 7 步逐步确认。这一步暴露了最严重的问题：**打包预演失败仍可确认落盘**——演示中一个 58 处错误的坏接线被正确拦截后，确认按钮才真正成为"机器判据闸门"。随后做前端瘦身（9 tab 收 6 tab、进门就是输入框）、模型升级到 V4（deepseek-chat 退役）、加推理等级（功能规格/验收测试 = high，端口/实现/接入 = medium）、模型列表自动获取。最后是**提示词体检**：用户要求模拟每次对话、检查提示词——审查矛头从"AI 的输出"转向"AI 的输入"。抓到一个真 bug：05 号提示词因之前 git 事故丢失，真实模式直接崩溃；还有 6 条改进（占位符统一、输出格式约束、few-shot 示例）。 |

| 金句 | 删除必须对着清单删；没走过的路就是 bug 藏身处 |

## 第 10 幕 · 空框架补课：存储分离与存储对接（08-16 下午，轮 50-55）

| 项 | 内容 |
|---|---|
| 画面 | 配置面板三处存储位置（数据/日志/错误）+ 对接自检按钮；kv.json 落盘展示 |
| 旁白 | 空框架的真机补课暴露了一串问题。先是一个小事故：web 页面打不开——管理台被 smoke 清理误杀，测试与运行环境冲突，清理逻辑要区分自建实例和常驻实例。然后用户提出一个非常产品化的需求：**错误、日志、数据的存储位置不一样，应该分开，页面可控制**。于是有了三个独立目录：LOG_DIR（业务日志）、ERROR_LOG_DIR（错误记录）、DATA_DIR/SQLITE_PATH（数据），配置面板分别可改、底部实时显示。接着用户追问了一句让我冒汗的话："**数据接口和存储对接好了么？**"——查下来，确实没对接：USER_STORE 只是配置项，组合根里没有任何存储实现。**配置存在 ≠ 功能存在**。于是三层打通：通用 KV 存储适配器（memory/file/sqlite 一行切换）、组合根注入、配置面板加"写→读→删"对接自检。 |
| 金句 | 配置存在 ≠ 功能存在；存储位置分离：数据/日志/错误互不混放 |

## 第 11 幕 · 承载测试与收敛：让 AI 当第一个真实用户（08-16 下午，轮 56-60）

| 项 | 内容 |
|---|---|
| 画面 | 完整流水线演示（记录库存变动）：规格→测试→实现→接入→HTTP 冒烟 200/400→kv.json 落盘；四个修复 diff 依次展示 |
| 旁白 | 用户说："自己随便用它开发个功能，测试一下承载。"这是整段设计里最高价值的转折——**让 AI 自己当第一个真实用户**。我走完全部流程开发"记录库存变动"，结果抓到 4 个 mock 流程和静态检查永远给不出的缺陷：① 接入路由被插在 return 之后，**编译全绿但 HTTP 永远 404**——编译通过 ≠ 路由可达，判据要验行为不只验编译；② manifest 文本拼接产生 JSON 尾逗号，tsc 不查 JSON 直到面板读它才炸；③ 试玩面板实例只按配置版本缓存，接入新功能后仍用旧实例；④ 预演失败后人修了文件，流水线仍卡在旧结果——要能自动重试。用户又问"业务测试里为什么没有刚才测试的业务"——面板操作列表是写死的，改成**动态发现**：接入即出现，无需改前端。最后收敛：清除 demo 文件（**测试沉淀的是能力，不是文件**）、写明框架适合/不适合开发什么（判断标准一句话：**"完成"能否被机器判定**）、项目更名 featureunit-demo。 |
| 金句 | 承载测试要找"没人走的路"；编译通过 ≠ 路由可达；测试沉淀的是能力，不是文件；"完成"能否被机器判定？能 → 让 AI 写 |
